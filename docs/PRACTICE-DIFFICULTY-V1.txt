Practice 문제은행과 난이도 v1
2026-11-11 / practice-difficulty-1

이 문서는 과거 정책을 보존한 것이다. 현재 정책은 같은 폴더의 PRACTICE-DIFFICULTY-V2.txt를 확인한다.
현재는 Level 1=조표 없음, Level 2=최대 1개이며 조표 보정도 강화되었다.

무엇을 고정했나

클래식을 제외한 악보는 출처와 기존 단계명을 계산에 사용하지 않는다.
악보의 음정·리듬·조성감으로 내용 점수를 계산하고, 조표 부담과 실제 재생 속도를
반영한 최종 점수에 고정 커트라인을 적용한다. 문제은행이 늘어나도 커트라인을
자동으로 재계산하거나 각 레벨의 문제 수를 맞추지 않는다.

합의한 기준은 Level 1=취미생의 입문, Level 5=기존 중급, Level 9=기존 고급이다.
기존 중급의 점수 범위 약 39~55, 고급 약 74~93을 기준으로 경계를 잡았다.
이는 초기 운영 기준이며 학생의 정답률로 검증한 심리측정 척도는 아니다.
특히 Level 1의 취미생 적합성은 실제 사용 테스트로 확인해야 한다.

고정 커트라인: 반올림 전 원점수 사용, 경계값은 높은 레벨에 포함

Level 1:  0 <= 점수 < 7.5
Level 2:  7.5 <= 점수 < 9.5
Level 3:  9.5 <= 점수 < 13
Level 4:  13 <= 점수 < 30
Level 5:  30 <= 점수 < 55
Level 6:  55 <= 점수 < 62
Level 7:  62 <= 점수 < 68
Level 8:  68 <= 점수 < 74
Level 9:  74 <= 점수

레벨만 1~9이며 점수에는 100점 상한이 없다. 점수는 시험 채점 점수나 정답률이 아니다.
화면 표시를 소수점 한 자리로 반올림해도 분류에는 원래 값을 사용한다.

내용 점수: 앞서 악보 비교에 사용한 수치 모델을 공통 계산 함수로 옮겼다.

H: 부호 있는 음정의 다양성(Shannon entropy, 반음 간격을 -12~12 범주로 제한)
P: 서로 다른 pitch class 수
C: 현재 표기 조표의 기본 음계 밖에 있는 새 음의 비율
J: 인접한 새 음 사이 절대 반음 간격의 평균
N: 주박당 새 음의 수
U: 1 - 최적 장·단조 프로파일 상관(0 미만 상관은 0으로 제한)
S: 약박에서 시작해 다음 주박을 넘어 지속되는 음의 수 / 주박 수
T: 잇단음표인 새 음의 비율
E: 붙임줄로 연결된 실제 음 길이의 다양성(Shannon entropy)

A = H + 0.7P
B = 60C + 4J + 8N + 30U
R = 2S + T + E/4
sigmoid(x) = 1 / (1 + exp(-x))

내용 = 38*sigmoid(5*(A-10)) + 38*sigmoid(0.6*(B-50))
       + 19*B/(B+40) + 5*R/(1+R)

계수와 비선형 구조는 기존 비교 자료의 난이도 순서를 참고해 정한 것이다.
기존 자료가 잘 분리된다는 사실을 독립 검증이나 실제 학습자의 성공률로 해석하지 않는다.
프로파일 상관 U는 조성감의 단서이며 무조성의 확정 판정이 아니다.
프로파일 수치는 Krumhansl–Kessler 장·단조 24개를 사용한다.
기존 연구 코드의 출처: https://github.com/cuthbertLab/music21/blob/master/music21/analysis/discrete.py

계산의 세부 규칙

붙임줄은 한 번 들리는 음으로 합친다. 이조된 조표에서는 그 조표를 기준으로 C를 계산한다.
자연단음계에서 달라지는 이끔음 등도 실제 변화음으로 계산하며 단조라는 이름만으로
고정점을 더하지 않는다. 조표 없음과 C장조라는 표기는 구분해 보존한다.
조성감 U는 표기된 조성명 대신 실제 울리는 음의 길이별 분포로 계산한다.
전체 악보에서는 마디 사이 음정도 포함한다. 한 마디 점수에서는 이전 마디 음정을
물려받지 않는다. 마디 점수는 별도로 계산할 수 있지만 8마디 레벨 커트라인을
그대로 적용하지 않으며, 부분 구간 분석의 level은 null이다.

6/8·9/8·12/8은 점4분음표 단위, 3/8은 앱의 점4분음표 기준에 맞춰 한 주박으로 본다.
5/8은 2+3/3+2, 7/8은 2+2+3의 세 배치 중 당김음 수가 적은 경우를 사용하고
가능한 수의 범위도 남긴다. 이는 박 묶음 정보가 부족할 때의 보수적 추정이다.
6/4는 앱의 4분음표 템포 정책에 맞춰 여섯 주박으로 본다.
예비박 클릭 수는 위 분석 주박과 별개로 박자표 분자 수를 따른다.

조표와 속도

조표 보정은 레벨을 직접 올리는 후처리가 아니다. 최종 점수에 먼저 포함한다.
각 마디의 조표 개수를 k, 해당 조표가 영향을 주는 음이름 중 실제 새 음으로
나온 종류의 비율을 u라고 할 때:

  마디의 조표 부담 = min(8, k*k/6) * (0.5 + 0.5*u)
  조표 보정 K = 위 부담의 실제 마디 길이에 따른 가중평균

조표 0개면 K=0이다. 음이름 기준이므로 임시표로 취소해 쓴 경우도 해당 계열의
표기를 다룬 것으로 센다. k=6이고 모두 사용하면 K=6점이다. 단순한 선율은
조표만으로 9레벨까지 올라가지 않는다.

  최종 점수 = (내용 점수 + K) * (실제 4분음표 BPM / 박자별 기준 4분음표 BPM)

예: 내용 45, K=0, 기준 속도 -> 45점 Level 5
예: 내용 8, K=6, 기준 속도 -> 14점 Level 4
예: 내용 85, K=0, 기준 속도 -> 85점 Level 9
예: 50점 문제를 기준의 1.25배로 재생 -> 62.5점 Level 7

속도에 정비례하는 보정과 위 조표 계수는 초기 운영 가정이다. 실제 풀이 기록으로
검증해야 한다. Practice 문제은행은 현재 박자별 기본 템포로 분류한다.
원본 XML의 음원 표기 템포를 자동으로 재생 템포로 쓰지는 않는다.
4분=80, 점4분=55는 같은 숫자로 비교하지 않는다. 점4분=55는 4분=82.5이다.
새로 들어온 5/8·5/4·2/8·4/8은 4분=80, 4/2는 2분=48을 기준으로 한다.

반영 위치와 호환성

계산: backend/solfege/difficulty.py
커트라인·문항별 값: backend/content/practice-difficulty.json
새 문제: backend/content/practice-bank-catalog.json
원본 및 제외 목록: backend/content/source/practice-bank/
재현 스크립트: scripts/build_practice_bank.py

서버와 로컬 데모는 같은 manifest를 사용한다. Practice는 9개 레벨로 표시하고
레벨 안에서는 점수 순서로 보여준다. 클래스 구분은 collection=classical로 유지한다.
새 API 필드는 practice_level(정수), difficulty_score, difficulty_version이다.
difficulty의 기존 beginner/intermediate/advanced 값은 이전 클라이언트용으로 유지한다.
목록 page_size 기본값은 20, 허용 최대는 200이다. 새 iPad 앱은 이전 서버와도
연결할 수 있도록 50씩 불러온다.

기존 문제의 ID·MusicXML·저장된 응시는 변경하지 않는다. 현재 목록과 새 응시에
난이도 메타데이터를 붙인다. 중복으로 숨긴 이전 문제도 과거 응시에서 계속 열 수 있다.
Drills의 2/4마디 난이도와 클래식 문제 분류에는 이 8마디 커트라인을 적용하지 않는다.

출제 가능 여부와 난이도는 구분한다. 못갖춘마디·낮은음자리표·반복 확장이 필요한
악보나 표기 오류 등은 원본을 임의로 고치거나 자르지 않고 이유를 기록해 보류한다.
전체 악보는 inventory.json으로 추적하고 원본은 sources.zip에 보관한다.
