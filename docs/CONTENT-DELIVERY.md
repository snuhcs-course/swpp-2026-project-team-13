# 앱·서버 콘텐츠 분리

실제 iPad 설치본은 온라인 앱이다. 문제 목록·난이도·MusicXML·MuseScore 정답 이미지·빈 답안지와 미니게임 자료는 서버가 제공한다. 같은 API 서버를 사용하는 팀원도 같은 문제은행을 사용하고, 풀이 기록은 로그인 계정별로 분리된다.

## 무엇을 어디에 저장하는가

| 위치 | 저장 내용 |
|---|---|
| 서버 `backend/content` | 불변 문제 버전, 악보·정답 이미지·답안지, 난이도/문제 풀, 미니게임 카탈로그와 선율 XML |
| 앱 설치 파일 | UI, 필기·로컬 MIDI 재생 코드, 현재 피아노·악기 음색, 라이선스, 표기용 글리프, 작은 오프라인 데모 |
| 기기 Caches | API origin별 SHA-256 키를 쓰는 100MiB LRU 캐시. 재다운로드 가능한 문제 파일만 저장 |
| 기기 Application Support | 계정별 진행 중 응시의 자료, 필기, 제출 이미지, 미전송 기록. 재개를 위한 6종 미니게임 JSON도 고정 보관 |
| 운영 DB·업로드 저장소 | 회원, 응시, 자기채점, AI 결과, 사용자 제출 이미지. Git에 포함하지 않음 |

문제를 선택하면 자료를 먼저 준비하고 검증한 후 음원을 재생한다. Memory run은 필요한 선율 XML만 내려받고, Rhythm puzzle은 카탈로그·표기 자료를 재사용한다. 전송 실패 시 재시도할 수 있다. 다운로드를 끝낸 미니게임 자료는 재사용되지만, 완전한 오프라인 문제은행은 제공하지 않는다.

완료한 응시 화면을 나갈 때 템플릿·MXL·정답 이미지의 응시별 복사본만 정리한다. 필기·제출 이미지·응시 상태는 유지하고, 나중에 결과를 열면 필요한 문제 자료를 다시 준비한다. 진행 중인 응시의 파일은 이 정리를 하지 않는다.

## 빌드와 테스트

`scripts/app_content_policy.py`가 Xcode의 리소스 복사 후, 서명 전에 실행된다. 소스 `Resources`를 삭제하지 않고 빌드된 `.app`에서만 전체 문제 자료를 제외한다.

- iPad/device: 기본 온라인 설치본. `scripts/package-ipad.py`가 허용 목록 밖의 문제 자료 유입과 누락·변조를 검사한다.
- Simulator: 기본 전체 테스트 자료. `SORI_FULL_DEMO=NO`로 온라인 설치본과 동일한 리소스 구성을 검증한다.
- `SORI_FULL_DEMO=YES`: 개발·검사용 전체 데모. 기본 IPA 패키징에서는 허용하지 않는다.
- 작은 데모: Practice 3문제 + Exam 3문제, Memory 20구간, Rhythm 24문제. 실제 계정의 서버 문제 풀과 혼합하지 않는다.

기존 `frontend/.../Resources`의 대규모 파일들은 테스트·재현용이다. Git 저장소 크기와 앱 설치 크기는 다르다. 현재 음색을 유지하므로 음색 파일은 이 변경으로 줄이지 않는다.

## 팀원이 서버를 업데이트할 때

먼저 새 코드와 `backend/content`를 받아 기존 서버 배포 방식대로 API·worker 이미지를 다시 빌드·실행한다. DB를 지우거나 새로 만들 필요는 없다. 기존 문제 조회·시딩 절차는 그대로다. 그 후 새 앱을 설치해 같은 API 주소에 연결한다.

Git으로 공유하는 것은 서버 코드와 배포할 문제 자료다. `git pull`이 운영 DB를 복사하지는 않는다. 별도 서버를 만들면 동일한 자료와 시드 명령으로 문제은행을 구성하고, 회원·풀이 기록은 그 서버의 DB에 저장된다. `.env`, 토큰, 운영 DB와 사용자 업로드를 Git에 넣지 않는다.

## 새 콘텐츠를 추가할 때

1. 서버에 새 버전·새 해시로 게시한다. 이미 공개한 악보 파일을 덮어쓰지 않는다.
2. 미니게임 자료는 `client-content-manifest.json`의 이름→해시/크기/MIME와 해시→서버 경로를 갱신한다. 현재 자료 재현 스크립트는 `scripts/build_content_delivery.py`이다.
3. 전체 은행을 앱에 다시 넣어 조회 문제를 해결하지 않는다. UI용 자원이나 작은 데모를 추가할 때만 `app_content_policy.py`와 데모 인덱스를 수정한다.
4. `python scripts/test_content_delivery.py`, Django 배포 API 검사, Swift Core 검사와 실제 슬림 번들 통합 검사를 실행한다.

매니페스트는 기기에서 15분 동안 재사용한다. 서버 연결이 끊긴 경우 기존 유효 목록으로 이미 받은 파일을 사용할 수 있다. 인증 실패(401)는 오프라인 fallback으로 숨기지 않는다. 배포 순서는 **서버 → 앱**이다.
