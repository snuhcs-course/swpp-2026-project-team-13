Exam 문제은행 / 레이팅 v1
========================

현재 결정
---------
- 비클래식 1,937문제를 Practice 1,550개 / Exam 387개로 고정 분리한다.
- 레벨별 할당이 아니라 연속 난이도 점수 순서의 약 50문제 구간마다 약 20%를 추출했다.
- 완전히 같은 리듬과 상대 음정의 단순 이조본은 같은 풀로 묶었다.
- 기존 문제 ID, 악보 버전, 난이도 공식, 레벨 커트라인은 바꾸지 않았다.
- scripts/build_question_pools.py를 다시 실행해도 기존 소속은 바뀌지 않는다.
- 미니게임 문제 풀은 이번에 변경하지 않았다. 난이도 공식 적용 작업과 함께 재구성할 예정이다.

저장 위치
---------
backend/content/question-pools.json
frontend/IPadApp/IPadApp/Resources/question-pools.json (같은 내용, 로컬 데모용)

records[문제 UUID].pool이 practice / exam을 결정한다.
문제의 난이도 자체는 기존 practice-difficulty.json에 그대로 있다.

사용 흐름
---------
Exam → 기존 로딩 화면 → 도전 / 적정 / 쉬운 문제 선택 → 시험 준비 → 응시 → AI 채점
선택 화면은 현재 레이팅, 문제 점수, 내 레이팅 대비 편차만 표시한다.
조성·박자·템포는 선택 화면에 표시하지 않는다.
초기 레이팅은 7.0이다. 기존 계정도 레이팅 시스템 도입 시 이 값으로 시작한다.
이전 응시 기록은 보존하되, 과거 점수를 소급하여 레이팅에 반영하지 않는다.

추천과 중복 방지
---------------
GET /api/v1/exam/recommendations/는 사용자별 고정 추천 제안을 반환한다.
다시 들어가거나 GET을 반복해도 같은 추천이 유지된다.
응시를 생성하거나 레이팅이 갱신되면 다음 추천을 새로 만든다.
문제 공개 상태·버전 또는 사용 가능한 문제 수가 달라져도 추천을 다시 만든다.
레이팅과 문제의 실제 난이도 점수를 사용한다. 레벨 번호로 뽑지 않는다.
적정 문제는 현재 레이팅에 가까운 점수에서 뽑는다.
도전은 내 레이팅과 적정 문제보다 높은 점수, 쉬운 문제는 그 둘보다 낮은 점수다.
우선 목표 예상 점수 구간: 도전 55~70, 적정 75~85, 쉬운 88~95.
희소한 점수대에서는 방향이 맞는 가까운 후보로 넓힌다.
적정 후보는 정규화 좌표에서 0.5 이내로 제한한다.
남은 후보가 없으면 해당 버튼을 사용할 수 없다고 표시하고 이미 본 문제로 대체하지 않는다.

한 번 응시를 생성한 문제는 다시 새 Exam으로 만들 수 없다.
이미 진행했던 Practice 기록도 확인하여, 과거에 본 Exam 전용 문제를 추천하지 않는다.
중단한 시험은 기존 attempt를 이어서 풀 수 있다.
추천을 본 뒤 선택하지 않고 홈으로 나가면 같은 추천 세 개를 유지한다.
앱은 계정별 추천을 저장하여 재진입 시 즉시 표시하며, 강제 로딩 대기 시간을 두지 않는다.
백그라운드에서 다른 기기의 응시/채점 변경을 확인할 수 있지만 화면을 다시 로딩하지 않는다.
카드를 선택하는 순간 서버에 ready 응시를 생성하고 문제를 확정한다.
시험 준비/청음 시작 전에도 변경할 수 없으며, 실제 시험 시간은 start 요청에서만 시작한다.
미제출 또는 AI 채점이 미완료인 레이팅 Exam은 계정당 하나만 허용한다.
Exam 재진입 시 ready는 준비 안내, in_progress는 기존 시험, submitted는 채점/결과 화면으로 복구한다.
채점이 queued/processing/failed인 동안 새 문제를 선택할 수 없다. 실패는 같은 답안으로 재시도한다.
추천 API는 이때 choices=[]와 active_attempt_id를 반환하며, 신규 응시 생성도 서버에서 거절한다.
기존 버전에서 남은 여러 응시는 오래된 것부터 복구한다. 레이팅 도입 전 응시는 이 제한에서 제외한다.
결과 화면의 홈 이동은 언제나 가능하고, 다음 시험 버튼은 AI 채점 completed 후에만 활성화한다.
채점 완료로 레이팅이 반영되어도 다음 추천은 사용자가 다음 시험/Exam을 누를 때 준비한다.
같은 생성 요청의 통신 재시도는 같은 attempt를 반환하며 새 응시로 보지 않는다.
AI 채점의 기술적 실패는 같은 답안으로 재시도할 수 있다. 문제를 다시 푸는 것과 다르다.

레이팅 계산
-----------
R = 현재 사용자 레이팅, D = 문제 난이도, S = AI 점수/100, n = 완료된 레이팅 시험 수.

1) 연속 좌표 z(x)
   점수 기준점 [0, 7.5, 9.5, 13, 30, 55, 62, 68, 74]를
   좌표 [0, 1,   2,   3,  4,  5,  6,  7,  8]로 선형 연결한다.
   74 초과 구간은 난이도 6점당 좌표 1만큼 연장한다.
   서로 다른 난이도 구간의 점수 폭 때문에 변화량이 지나치게 달라지는 것을 줄이는 목적이다.
   경계에서 연속이며, 레벨을 반올림하여 추천하거나 갱신하지 않는다.
   이 변환은 exam-rating-1에 고정되어 있다.

2) 예상 점수 비율
   E = sigmoid(ln(4) + (z(R) - z(D))/0.5)
   R=D라면 E=0.8이다. 즉 내 레이팅은 같은 난이도에서 평균 80점을 기대한다는 의미다.

3) 반영 강도
   K = 0.25 + 0.5 × exp(-n/5)
   처음에는 빠르게 조정하고, 기록이 쌓이면 안정시킨다. 장기적으로도 0.25 아래로 줄지 않는다.

4) 갱신
   step = clamp(K × (S-E), -0.5, +0.5)
   R_new = z의 역함수(max(0, z(R)+step))
   표시 변화량 = R_new - R

한 시험은 관측 한 번이다. 점수 100개를 각각 독립 표본으로 세지 않는다.
0점도 정상적인 평가 결과다. 사용자 레이팅에는 100점 상한을 두지 않는다.
같은 시험 점수라면 어려운 문제를 풀수록 변화량이 유리하다.
이 모델은 검토한 시뮬레이션의 제품 초기 정책이며 실제 학습 데이터로 검증된 능력 측정 척도는 아니다.

채점과 저장
-----------
새 시험은 ai-melodic-v2 / grading-prompt-v3.txt를 사용한다.
빈 마디는 미응답, 애매한 표기는 해당 부분 오답으로 평가하고 숫자 점수를 반드시 반환한다.
기존 needs_review 결과를 임의의 점수로 바꾸지는 않는다.
통신 실패·시간 초과·계약에 맞지 않는 응답은 기술적 실패로 처리하며 레이팅을 바꾸지 않는다.

문제 점수와 난이도/풀/레이팅 정책 버전은 생성 시 Attempt.exam_rating_snapshot에 고정한다.
채점 완료 시점의 사용자 레이팅을 기준으로 갱신한다. 동시 완료는 DB 잠금으로 순서를 정한다.
채점 완료 상태와 레이팅 변화는 하나의 DB 트랜잭션으로 저장한다.
ExamRatingChange는 attempt당 한 행이므로 새로고침·작업 재실행으로 중복 반영되지 않는다.
Practice 자기채점과 미니게임은 이번 레이팅에 반영하지 않는다.
계정 삭제 시 레이팅과 추천 제안, 레이팅 변화 기록도 함께 삭제한다.

직접 확인하기
-------------
1. 새 버전 앱과 새 버전 API·채점 워커를 함께 사용한다. 이전 API는 새 선택 화면을 지원하지 않는다.
2. 계정으로 로그인하고 Exam에 들어가 레이팅 7.0과 문제 점수/편차를 확인한다.
3. 뒤로 갔다가 다시 들어갔을 때 같은 세 문제인지 확인한다.
4. 하나를 선택하여 응시하고 제출한다. 채점 후 점수와 레이팅 전후 값, 변화량을 확인한다.
5. 결과를 여러 번 새로고침해도 변화가 중복 적용되지 않는지 확인한다.
6. 다음 Exam에서 방금 선택한 문제가 다시 나오지 않는지 확인한다.
7. 중단한 시험은 홈의 이어서 하기에서 복구한다.

서버 갱신(저장소 루트, 기존 backend/.env 필요):
docker compose --env-file backend/.env up --build -d --wait
boot.py가 새 DB 마이그레이션과 문제 시드를 적용한다.
실제 AI 채점은 기존 서버의 AI 제공자 키 설정이 필요하다. 결과가 실패하면 같은 답안으로 재시도한다.
로컬 데모에서도 선택·저장·레이팅 변화를 시험할 수 있지만 데모 점수는 실제 필기를 채점한 결과가 아니다.
