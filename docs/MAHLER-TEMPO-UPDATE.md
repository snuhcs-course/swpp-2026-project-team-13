# 말러 문제와 원본 재생 템포

사용자가 제공한 `classic/mahler.mscz`, `mahler.txt`를 기존 단선율 시험 형식으로 추가했다. 말러 13개를 새 UUID·버전 1로 등록해 **연습실 113개 + 클래식 34개**가 된다. 리듬 게임, 로그인, 자기채점, 화면 구성 등 다른 앱 기능은 변경하지 않는다.

원본 138마디 중 13개 선율은 각각 정확히 8개의 완전한 마디다. 81–88마디와 113–138마디는 전부 쉼표여서 제외했다. 마지막 음악 구간의 일부인 80마디 온쉼표는 그대로 남겼다. 원본 노트·쉼표·붙임줄을 비교해 음정과 길이가 바뀌지 않은 것을 검사한다. 각 문제의 정답은 기존 MuseScore 4.6.3 렌더러로 4+4마디 두 단에 생성했다. 조표와 빈 오선도 기존 형식을 사용한다.

`sori-score-tempo-1`은 이 23개 문제에만 사용하는 원본 고정 템포 정책이다. 원본의 메트로놈 음표·점·BPM을 읽고 MusicXML의 `sound tempo`(4분음표 BPM)와 일치하는지 검사한다. 앱의 기존 템포 라벨은 원본 음표 기준을 표시한다. 점2분음표를 지원하기 위해 템포 환산에 3배 계수를 추가했다. 기존 문제의 박자별 연습 템포 정책은 바꾸지 않는다.

기존 음악 파일은 정규화된 악보 파싱 템포 96을 유지한다. 실제 재생은 응시에 저장된 `tempo`와 `tempo_bpm`이 담당한다. 같은 시계로 선율·음계·예비박을 재생하며 권장 종료 시간도 해당 속도로 계산한다. 로컬 데모가 원본 템포를 기본값으로 덮어쓰지 않게 했다. 기존 응시는 저장된 원래 재생 계획을 유지하고 새 응시부터 원본 속도를 쓴다.

기존 클래식 21개와 새 말러 13개를 모두 자연스러운 순서로 배치한다. `classical-question-order.json`은 작곡가 안에서 교향곡 → 협주곡 → 소나타 → 다른 작품 순으로, 작품 번호·악장·주제·Op./No.를 숫자로 비교한 UUID 목록이다. 말러는 교향곡 1·6·7·9번, 브람스는 교향곡 1·2·3·4번과 악장 순이며 가곡과 협주곡은 그 뒤에 나온다. 차이콥스키 Op.39 No.9도 No.18보다 먼저 나온다. 서버 등록은 `Question.order`만 갱신하고 버전·기록을 덮어쓰지 않는다. 로컬 데모도 같은 순서 파일을 사용한다.

클래식 목록은 페이지당 50개를 요청해 현재 34개와 작곡가 9명이 첫 조회에서 모두 보인다. 기존 화면과 페이지 이동 방식은 유지한다.

재생성:

```powershell
$sheetCode = Get-Content -Raw -LiteralPath scripts/build_classical_sheets.ps1
& ([scriptblock]::Create($sheetCode)) -Repository (Get-Location).Path -Compact
python scripts/import_mahler_questions.py --render
python scripts/test_classical_updates.py
```
