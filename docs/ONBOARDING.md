# 온보딩: 회원가입 · 학습 목표 · 로그인

첫 실행은 **회원가입 → 학습 목표 선택 → 메인 홈**으로 이어진다. 서버 API는 [API 계약 v0.10.0](sori-api/API-CONTRACT.md), 코드는 `frontend/IPadApp/IPadApp/Views/AuthFlowView.swift`부터 보면 된다.

## 어떤 화면이 먼저 열리는가

| 상황 | 첫 화면 |
| --- | --- |
| 새로 설치, 빌드에 서버 주소 있음 | 회원가입 |
| 새로 설치, 빌드에 서버 주소 없음(`API_BASE_URL` 비어 있음) | 로컬 데모 |
| 이 기기에서 계정을 쓴 적 있음(`sori.accountUsed` 또는 저장된 토큰) | 로그인 |
| 서버가 `signup_enabled=false`를 알려 줌 | 로그인(회원가입 링크도 숨김) |
| 유효한 토큰이 있음 | 메인 홈(목표가 없으면 학습 목표 선택) |
| 기존 설치에 데모 선택(`sori.demo`)이 저장돼 있음 | 그 선택을 유지 |

인증 화면은 사이드바 없는 전체 화면이다. 오른쪽 위 아이콘으로 **연결 설정**에 들어가 서버 주소와 로컬 데모를 바꾸고, **돌아가기**로 돌아온다.

## 회원가입

- 입력란은 아이디 → 닉네임 → 비밀번호 → 비밀번호 확인 순서로 한 칸씩 펼쳐진다.
- 앞 칸이 유효하고 0.35초 동안 입력이 멈추면 다음 칸을 연다. 포커스는 옮기지 않으며, 키보드의 다음 키를 누르면 바로 열고 이동한다.
- 펼친 칸은 앞 칸을 고쳐도 접지 않는다. 동작 줄이기 설정에서는 애니메이션 없이 표시한다.
- 아이디와 로그인 아이디 칸은 영문 키보드로 연다. 그래서 관리자가 영문이 아닌 아이디를 만들었다면 붙여넣기로 입력해야 한다.
- 비밀번호 확인은 같은 비밀번호를 입력하는 동안에는 오류를 띄우지 않고, 달라진 순간부터 표시한다.
- 앱의 검사는 안내용이다. 흔한 비밀번호·아이디 유사성·아이디 중복은 서버만 판단한다.
- 아이디 중복은 회원가입을 누른 뒤에야 알 수 있다. 전용 확인 API는 아직 없다. 409를 받으면 아이디 칸으로 돌아가 **아이디만 바꿔 주세요**를 표시한다.
- 요청 실패 후에는 보안을 위해 비밀번호 두 칸을 비우고 다시 입력받는다. 닉네임과 펼침 상태는 유지한다.
- 비밀번호를 복구할 수 없다는 안내는 서버 오류가 있을 때도 항상 표시한다.

## 학습 목표

가입 요청에는 학습 목표를 보내지 않는다. 계정이 생긴 뒤 `UserProfile.learning_goal == null`이면 메인 대신 목표 선택 화면을 보여 주고, **시작하기**에서 `PATCH /me/`로 저장한다. 저장에 실패하면 화면에 남아 오류를 알린다. 고르기 전에 앱이 꺼지면 다음 실행·로그인 때 다시 나타난다.

선택지는 서버 값 그대로다: 예중·예고 입시, 음대 입시, 중등 음악 임용, 예중·예고 재학생, 기타. 나중에는 연결 설정이나 Practice 화면의 목표 표시에서 바꿀 수 있다.

## 로그인과 로그인 상태 유지

**로그인 상태 유지**는 기본 켜짐이고 API 변경이 필요 없다.

| | 켜짐 | 꺼짐 |
| --- | --- | --- |
| 토큰 위치 | Keychain | 메모리(이 실행 동안만) |
| 앱 재실행 | 자동 로그인 | 다시 로그인 |
| 연결 설정의 서버 연결·데모 전환 | 유지 | 유지(같은 서버일 때만 토큰 사용) |
| 이 서버의 이전 저장 토큰 | 교체 | 삭제 |

- 꺼도 서버 토큰은 폐기되지 않는다. 토큰은 사용자당 하나라 폐기하면 다른 기기도 로그아웃되기 때문이다.
- 꺼져 있으면 iOS가 백그라운드 앱을 종료했을 때도 다시 로그인해야 한다. 필기는 기기에 저장돼 같은 계정으로 로그인하면 이어진다.
- 로컬 기록은 끈다고 지워지지 않는다. 계정별로 분리돼 다른 사용자에게 보이지 않을 뿐이다.
- 회원가입은 체크박스가 없고 항상 토큰을 저장한다.

아이디·비밀번호 오류와 시도 제한은 창을 띄우지 않고 비밀번호 칸 아래에 표시하며, 대기 중에는 버튼에 남은 시간을 보여 준다. 그 밖의 오류는 기존처럼 확인 창으로 알린다.

## 배포 시 주의

- 서버와 앱을 함께 올린다. 구버전 앱은 목표가 `null`인 계정의 프로필을 해석하지 못한다. 새 서버에서 구버전 앱의 가입(목표 포함)은 그대로 동작한다.
- 마이그레이션 `0006_learning_goal_optional`은 기존 값을 바꾸지 않는다.
- `0005`로 되돌릴 수는 있지만, 목표가 `null`인 계정은 모델 기본값 `other`로 채워져 "기타"를 고른 계정과 구분되지 않는다.
