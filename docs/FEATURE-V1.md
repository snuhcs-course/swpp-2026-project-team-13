# Solfège 악보 Feature v1 명세

확정일: 2026년 11월 1일 · 명세 버전: `1.0.0` · 대상: 프론트엔드와 백엔드 개발자

**Feature는 악보에 무엇이 들어 있는지 설명하는 공통 데이터다.** 문제 검색과 구성, 미니게임 구간 선택, 생성 문제 검증에 사용하고, 풀이 기록과 연결해 학습 경향을 관찰한다. 특정 feature가 있는 마디를 틀렸다는 이유만으로 그 feature를 학생의 약점으로 확정하지 않는다.

이 문서는 공통 규칙을 확정한다. `backend/solfege/features/`에 v1 추출기와 구간 분석을 구현했고, DB 저장 모델·migration·관리 명령을 추가했다. 현재 앱의 제출 API와 화면에는 아직 연결하지 않았다. 기존 `feature-lab-0.2` 실험 결과와는 버전을 구분한다. [구현 상태와 실행 방법](feature-v1/IMPLEMENTATION.md)을 참고한다.

## 먼저 읽을 내용

팀원은 이 문서로 목적과 사용 규칙을 확인한다. 추출기나 저장 구조를 구현할 때는 [정확한 계산과 데이터 규칙](feature-v1/EXTRACTION-RULES.md)을 함께 따른다. [두 마디 예시 데이터](feature-v1/example.json)와 [예시 악보 XML](feature-v1/example.musicxml)은 경계를 넘는 도약이 어떻게 분리되는지 보여준다.

예시 악보는 `도4 솔4 미4 솔4 | 도4 레4 미4 파4`이며 모두 4분음표다. 총 발음 시작 8회, 음정 연결 7회, 마디 안 5도 상행 1회, 마디 경계 5도 하행 1회다. 2마디만 가져오면 그 마디의 5도 하행은 0회다. 두 마디의 기보 리듬은 같아서 리듬 반복 비율은 1/2이다.

## 1 앞으로 사용할 곳

| 기능 | Feature의 역할 |
| --- | --- |
| Practice | 문제를 고르고, 자기채점한 마디와 그 마디의 특징을 연결한다. |
| Exam | 이번 문제의 특징과 근거가 있는 과거 관찰을 AI 피드백에 제공한다. |
| 미니게임 | 목표에 맞는 구간을 찾고, 실제로 연습한 구간과 과제 종류를 기록한다. |
| 문제 생성 | 원하는 특징으로 생성 조건을 만들고, 생성된 XML을 다시 분석해 조건을 확인한다. |
| 난이도와 추천 | 분석 지표로 초기 순서를 만들고, 실제 풀이 기록으로 적절성을 검토한다. |

공통 기반은 유지하면서 각 기능의 계산과 판단은 별도로 바꿀 수 있어야 한다. 예를 들어 난이도 가중치를 바꿔도 음표와 도약 기록을 다시 작성할 필요는 없다.

## 2 악보를 네 가지 범위로 본다

| 범위 | 예시 | 사용할 때의 원칙 |
| --- | --- | --- |
| 마디 내부 `local` | 3마디 안에서 솔4 → 도4로 하행 | 그 마디만 가져가도 성립한다. |
| 마디 사이 `connection` | 3마디 마지막 솔4 → 4마디 첫 도4 | 두 음이 모두 있는 구간에만 적용한다. |
| 다른 구간과의 관계 `context` | 4마디의 리듬이 1마디와 같음 | 비교 대상 마디도 근거로 보관한다. |
| 문제 전체 `score` | 전체 음역과 특징의 분포 | 한 마디의 고유 태그로 복사하지 않는다. |

모든 파생 특징에는 **근거 음표 ID와 마디 번호**를 남긴다. 한 음의 길이와 같은 원본 값은 해당 음표 자체가 근거다.

### 마디 경계 예시

1마디 마지막 음이 솔4, 2마디 첫 음이 도4라면 두 음 사이에는 5도 하행이 있다.

- 문제 전체: 5도 하행 1회로 집계한다.
- 2마디 내부 특징: 이 하행을 포함하지 않는다.
- 1~2마디 미니게임: 두 음이 모두 있으므로 포함한다.
- 2마디만 사용하는 미니게임: 첫 음 앞의 하행을 가져오지 않는다.

붙임줄로 바깥 마디와 이어진 구간은 바로 독립 문제로 쓰지 않는다. 음의 시작과 길이를 바꾸어 다시 분석하거나 다른 구간을 고른다.

## 3 무엇을 추출할지 확정한다

### 음정과 음높이

| 항목 | 뜻 |
| --- | --- |
| 실제 음높이 | 옥타브를 포함한 MIDI 음높이와 원래의 음이름 표기 |
| 음정 간격과 방향 | 연속된 발음 시작 사이의 반음 간격, 기보상의 도수, 상행·하행·동음 |
| 큰 상행과 하행 | **기보상 5도 이상**이면서 실제 음높이가 올라가거나 내려가는 연결 |
| 음역 | 구간의 가장 높은 음과 낮은 음 사이 반음 수 |
| 적힌 임시표 | 악보에 실제 표시된 샤프·플랫·제자리표 등 |
| 조표와 다른 음 | 해당 위치의 조표가 정한 음과 실제 음높이의 변화량이 다른 발음 시작 |

**5도 이상과 7반음 이상은 별도 값이다.** 도–솔♭은 감5도라서 5도 이상에 해당하지만 6반음이다. 도–파♯은 증4도라서 6반음이어도 5도 이상에는 해당하지 않는다. 난이도 실험에서 사용하는 7반음 이상 비율과 혼용하지 않는다.

주의 임시표는 원본 XML이 `cautionary="yes"`로 표시한 경우를 별도로 기록한다. 앞마디를 보고 표기를 권장해야 하는지 판단하는 일은 채점 규칙의 역할이다. 조표가 없으면 조표 관련 값은 미확정으로 둔다. 화면 표시나 실험을 위한 다장조 가정은 원본 feature에 덮어쓰지 않는다.

### 리듬과 표기

| 항목 | 뜻 |
| --- | --- |
| 시작 위치와 길이 | 마디 시작부터의 위치와 음가를 정확한 분수로 보관 |
| 쉼표 | 쉼표의 위치와 길이 |
| 점음표와 잇단음 | 적힌 점의 수, 잇단음 비율과 적용 이벤트 |
| 붙임줄 | 적힌 음표는 각각 유지하고, 실제로 한 번 발음되는 음은 하나로 연결 |
| 박 안의 위치 | 해당 박에서 어느 위치에 음이 시작하는지 |
| 마디 리듬 패턴 | 음높이를 빼고 음표·쉼표·붙임줄 지속의 위치와 길이를 비교 |
| 빔 | 적힌 묶음을 보존하고, 기본 박 경계를 넘는 묶음은 검토 후보로 기록 |

여기서 이벤트는 악보에 적힌 음표 또는 쉼표 하나를 뜻한다. **적힌 음표 수와 실제 발음 시작 수는 구분한다.** 4분음표 두 개를 붙임줄로 연결했다면 적힌 음표는 2개, 발음 시작은 1개다.

6/8의 분석용 기본 박은 점4분음표라서 한 마디에 2박이다. 앱 예비박에서 8분음표를 6번 세는 재생 규칙과는 구분한다.

### 반복과 밀도

같은 문제 안에서 기보 리듬 패턴이 정확히 일치하는 마디를 연결한다. 음높이와 빔 모양은 이 비교에 영향을 주지 않는다. 붙임줄로 적힌 방식은 패턴에 반영한다.

발음 시작 수, 쉼표 수, 박당 발음 시작 수, 전체 마디 수를 함께 보관한다. **유사한 리듬이나 선율의 반복 판별은 v1의 필수 범위에 포함하지 않는다.** 현재는 정확한 리듬 일치부터 제공하고, 선율 원본 데이터를 보관해 이후 확장한다.

## 4 사실과 해석을 구분한다

| 구분 | 예시 | 해석 |
| --- | --- | --- |
| 원본 사실 | 솔4, 길이 1/2, 붙임줄 시작 | XML에 적힌 내용을 읽은 값 |
| 규칙으로 얻은 특징 | 5도 하행, 같은 리듬의 반복 | 명시된 규칙을 적용한 결과 |
| 검토 후보 | 박을 넘는 빔, 당김음 후보 | 더 살펴볼 위치이며 자동 오류 판정이 아님 |
| 실험 지표 | 조성 분포 적합도, 종합 난이도 | 계산법과 기준 집단에 따라 바뀌는 참고값 |

빔이 박을 넘는다고 항상 표기 오류인 것은 아니다. 조성 분포 적합도가 낮다고 무조로 확정하지 않는다. Feature 추출과 음악적 정오 판단은 분리한다.

모르는 값은 `null`과 사유로 표현한다. **미확정을 0회나 특징 없음으로 바꾸지 않는다.**

## 5 기록과 연결하는 방식

문제 분석과 사용자 풀이 기록은 별도로 저장하고 문제 버전·구간으로 연결한다.

- **문제 쪽:** XML 해시, 분석 버전, 이벤트, 마디, 특징의 근거, 집계값.
- **풀이 쪽:** 사용자, 모드·과제 종류, 실제 구간, 템포·반복 청취·대기 조건, 제출과 채점 완료 상태.
- **결과 쪽:** 오류 위치·범주와 자기채점·AI·기계채점 출처. 인식 불확실과 표기 권장은 실제 오류와 구분.

Practice의 음정·리듬·기타 복수 선택은 그대로 보관한다. 마디의 모든 feature를 각각의 오류 원인으로 변환하지 않는다. Feature별 경향을 볼 때는 오류뿐 아니라 **그 feature가 있는 마디를 풀고 채점한 기회**도 센다. 같은 응시의 같은 마디에 동일 feature가 여러 번 나와도 마디 단위 관찰에서는 1회다.

미니게임 결과는 그 게임이 실제로 요구한 능력 범위에서 해석한다. 예를 들어 현재 멜로디 런은 정답 리듬이 주어진 상태에서 음높이를 입력하므로, 결과를 독립적인 리듬 받아쓰기 능력으로 집계하지 않는다.

선율 길이·반복 구조는 문제 특징이고, 기억 대기 시간·청취 횟수는 과제 조건이다. 이 기록을 이용해 관계를 살펴보되 v1에서 기억력이나 개인 약점 점수를 확정하지 않는다.

## 6 난이도는 별도 실험으로 유지한다

현재 비교 화면의 C 방식은 음정 부담·리듬 부담·조성 분포 지표를 조합한 **실험 버전**으로 남긴다. 100은 만점이 아니며, 200이라고 체감 난이도가 두 배라는 뜻도 아니다. 세부 계산은 [개발 규칙의 난이도 항목](feature-v1/EXTRACTION-RULES.md#8-난이도-실험과의-분리)을 따른다.

현재 계산에는 실제 템포, 재생 횟수, 학생의 실력이 반영되지 않는다. 서로 다른 박자의 정규화 점수도 그대로 같은 절대 난이도로 해석하지 않는다. 이후 실제 풀이 결과를 이용해 유용성을 확인하고 계산 버전을 교체할 수 있다.

## 7 지원 범위와 완료 기준

v1의 우선 대상은 MusicXML 또는 MXL의 한 파트·한 성부·한 보표 단선율이다. 정수 반음, 음표·쉼표·붙임줄·기본 잇단음을 다룬다. 다성부·화음·꾸밈음·미분음 등 미지원 입력은 이유와 함께 제외한다. 반복기호는 펼치지 않고 적힌 마디 순서로 분석한다.

못갖춘마디는 실제 길이를 유지한다. 7/8처럼 박 묶음이 필요한 박자는 묶음 정보가 없으면 박 기반 특징을 미확정으로 둔다. 자세한 지원 조건은 개발 규칙에 명시한다.

명세 확정과 구현 완료는 구분한다. v1 구현 완료 시 아래 항목을 확인한다.

- [ ] 같은 XML·설정·추출기 버전에서 같은 음악 분석 결과가 나온다.
- [ ] 붙임줄로 음을 나누어 적어도 실제 발음 시작과 총 지속시간이 유지된다.
- [ ] 마디 경계 도약이 단일 마디의 고유 특징에 섞이지 않는다.
- [ ] 구간을 자르면 외부 근거를 가진 특징이 빠지고 붙임줄 의존성이 표시된다.
- [ ] 조표 미명시·분모가 0인 비율·미지원 박 묶음이 0으로 위장되지 않는다.
- [ ] 실제 악보와 나란히 보며 특징의 근거를 확인할 수 있다.
- [ ] 원본 악보 검수 상태와 추출 성공 여부가 구분되어 보관된다.
- [ ] 문제·마디 특징을 재계산해도 과거 풀이와 결과 원본이 유지된다.

## 8 이번 결정 이후의 작업

이 명세에 맞는 공통 분석 저장 형식과 변환기를 먼저 구현한다. 이후 Practice 자기채점 기록을 연결하고, 모드별 관찰 통계와 Exam의 개인화 조언을 순서대로 추가한다. 문제 생성·미니게임도 같은 분석 데이터를 사용한다.
