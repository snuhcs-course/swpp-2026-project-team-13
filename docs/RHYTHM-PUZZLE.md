# Rhythm puzzle

Drill의 **Memory run**과 같은 크기의 카드에서 선택한다. 실제 선율 두 마디를 듣고 리듬 조각과 타이로 답한다. AI 호출이나 필기 인식은 사용하지 않는다. 현재 출제 버전은 `rhythm-puzzle-v3`다. 기존 `v1`·`v2` 파일과 기록은 보존하며 서버는 세 버전을 모두 받는다.

## 이번 버전에서 플레이할 내용

- 출제 풀은 **141원곡에서 531구간**이다. 기존 일반 문제 415구간의 등급을 유지하고, 기존 클래식 악보에서 30원곡·116구간을 추가했다. 프로코피예프·차이콥스키·베토벤·그리그·생상스·사티·드보르자크·브람스·말러 선율이 기존 풀에 무작위로 섞인다. 클래식의 출제 가능 구간은 초급 57개·중급 46개·고급 13개다.
- 클래식만 기존과 같은 `rhythm-burden-v1` 식으로 평가해 같은 박자 v3 풀 안의 순위 점수 0–33 / 34–66 / 67–100으로 임시 등급을 부여한다. 일반 문제의 기존 등급은 재분류하지 않는다. 실제 학습자 기록으로 보정한 등급은 아니다.
- 난이도는 **초급 / 중급 / 고급**, 기본은 초급이다. 한 세트는 5문제다. 같은 원곡은 한 세트에서 한 번만 사용하고, 같은 박자 안의 실험 난도 하·중·상 구간을 섞는다. 초급 보기는 원곡보다 더 잘게 나뉜 음가나 새로운 잇단음이 갑자기 나오지 않도록 제한한다(기본 8분음표는 허용).
- 하단 보기는 **4열×3행, 총 12개**다. 정답 조각을 모두 포함하고 나머지는 원본 풀에서 길이가 비슷한 조각으로 채운다. 보기 순서는 문제 시작 때 섞고 이후 유지한다. 같은 조각을 여러 번 사용할 수 있다.
- 새 문제와 다시 듣기는 모두 **1초 대기 → 예비박 한 마디 → 실제 음높이의 피아노 선율 두 마디** 순서다. 대기 중 중복 재생은 거절하고, 화면 비활성·닫기에서는 지연 작업을 취소한다. 취소된 대기는 청취로 기록하지 않는다. 예비박과 선율은 하나의 오디오 시계에 예약한다. 6/8에서는 8분음표 간격으로 여섯 번, 첫 박을 강하게 친다. 선율 재생 중에는 클릭을 계속하지 않는다.
- 일반 문제의 템포는 기존 박자별 재생 정책에서 고정한다. 클래식에 표기 템포가 있으면 기존 클래식 메뉴의 최신 문제 버전과 같은 템포로 재생한다. 클래식이 나오면 `브람스 자장가 中` 형태로 작곡가와 원곡명을 작게 표시한다. 입력은 재생 중에도 가능하지만, 최초 재생 또는 재청취를 한 번 끝까지 마쳐야 제출할 수 있다.

## 조각과 입력

기본 조각은 한 박 패턴이다. 4/4·3/4는 4분음표, 6/8·9/8·12/8은 점4분음표가 기본 박이다. 2/4도 지원한다.

원본 음표를 박 경계에서 강제로 자르지 않는다. 2분음표는 2박, 점4분음표는 1.5박을 차지한다. 두 박을 차지하는 셋잇단음 묶음도 하나의 조각으로 유지한다. 내부 시간은 4분음표=1인 정확한 기약분수다. 반박에 제한하지 않는다.

- 탭: 시간상 가장 이른 빈 위치에 넣는다.
- 드롭: 길게 누르는 시스템 드래그 대신 이동 거리 0에서 시작하는 제스처로 바로 끌어 놓는다. 빈 박의 가운데에 놓아도 박 시작에 배치한다. 긴 음 뒤에 남는 반 박은 정확한 분수 위치를 유지한다. 이미 채운 조각 위에 놓으면 그 조각을 교체하되, 다른 조각까지 침범하면 거절한다. 정답 표시의 좌표는 드롭 대상에 포함하지 않는다.
- 삭제: 명시적인 사각형 터치 영역을 가진 조각을 탭한다. 긴 조각도 전체가 삭제되며 뒤 조각은 앞으로 당겨지지 않는다.
- 되돌리기: 배치·교체·삭제·타이 작업을 복구한다. 진행을 다시 열어도 남아 있다.
- 타이: 오른쪽 아래 일회용 타이 버튼을 켜고 다음 조각을 넣는다. 이미 채웠다면 타이를 켜고 이웃한 두 조각을 차례로 선택한다. 이미 놓인 조각의 상자 어느 곳에서든 이웃 조각 상자까지 그어 연결한다. 양방향·마디 경계를 지원한다. 같은 연결을 다시 그어도 유지하며 삭제는 붙임줄을 탭한다. 시간상 맞닿은 끝 음표와 첫 음표에만 연결된다. 쉼표와는 연결하지 않는다. 마디 사이도 연결 가능하다.
- 조각 삭제·교체 시 그 조각 양옆 타이를 함께 제거한다. 타이의 터치 영역과 조각 삭제 영역을 나눈다.
- 1박 초과는 연한 파랑, 1박 미만은 연한 보라와 길이 숫자로 안내한다. 선택·드래그에 가벼운 높이감과 그림자를 사용한다.

## 악보와 화면

조각 136종은 **MuseScore Studio 4.6.3 / Leland**에서 미리 조판한다. 검증된 SVG 윤곽과 음표 머리 좌표를 `rhythm-engraving-v3.json`에 고정해 iPad Canvas에서 그린다. 이전 버전 조각도 모두 포함한다. 앱 실행 시 MuseScore 설치·서버 렌더링은 필요하지 않다. 음표·쉼표·빔·점·잇단음과 조각 내부 타이는 MuseScore 출력 그대로다. 타이 도구 아이콘은 제공된 그림처럼 두 4분음표를 붙임줄로 연결한 벡터다.

조각 내부 간격은 고정이며 화면 폭에 맞춰 늘리지 않는다. 마디는 조각의 고유 폭과 빈 박의 적당한 여백으로 배치하고, 공간이 부족할 때만 전체를 함께 축소한다. 큰 박자표, 오선과 마디선으로 실제 리듬 악보 형태를 유지한다.

조각 사이 붙임줄은 양 끝 음표 머리 좌표 바로 아래에 끝이 가늘고 중앙이 조금 두꺼운 곡선으로 그린다. 같은 줄의 마디 경계는 연속해서 연결한다. 줄이 바뀌면 줄 끝에서 이어지는 열린 반쪽 곡선으로 나누어 표시한다. 연결 조합마다 별도 이미지를 만들지 않는다.

평소 화면에는 진행률·박자·템포·실험 난도·필수 조작만 표시한다. 상세 설명은 첫 실행의 4단계 튜토리얼로 분리하며 물음표로 다시 열 수 있다. 제출 후 피드백은 지연하지 않는다.

## 채점과 피드백

음높이와 기보 모양을 제외하고 **발음 시작 시점·지속시간·쉼표**를 비교한다. 2분음표와 타이로 이은 4분음표 두 개는 같은 정답이다. 원본의 기보 리듬 해시를 그대로 채점에 쓰지 않는다.

| 결과 | 화면 |
|---|---|
| 정답 | 짧은 초록색 확인과 다음 문제 버튼 |
| 첫 오답 | 오답 사실만 전달. 틀린 위치나 맞은 칸은 공개하지 않음 |
| 두 번째 오답 | 마지막 제출의 오류 위치를 바탕으로 마디·박 힌트 제공 |
| 세 번째 오답 | 입력한 답을 유지하고 그 아래 정답 리듬과 정답 듣기를 제공 |

세 번째 오답은 `revealed`, 스스로 맞힌 경우는 `correct`로 구분한다. 수정 후 정답과 첫 제출 정답도 구분해 보관한다. 중복 HTTP 요청은 새로운 시도로 세지 않는다.

## 난이도와 검토 기록

`rhythm-burden-v1`은 실험 점수다. 약한 위치에서 시작해 더 강한 위치를 가리는 지속음의 부담을 우선하고, 시작 위치·분할 격자 변화·기보 잇단음 비중·패턴 다양성을 추가한다. 음표 밀도의 가중치는 작다. 규칙적인 16분음표보다 엇박 지속음이 더 높게 평가되는 회귀 사례를 검사한다.

현재 원시값은 `4×박 위치 어긋남 + 0.25×박 밖 시작 비율 + 격자 변화 비율 + 잇단음 비율 + 0.5×패턴 다양성 + 0.05×밀도`다. 같은 박자 출제 풀 안에서 동점의 중간 순위로 0–100 표시값을 만든다. 예측 정답률·절대 실력 점수가 아니다. 서로 다른 박자의 점수를 같은 절대 난도로 해석하지 않는다. 데이터베이스에서 흔한 패턴을 곧바로 학습자에게 익숙한 패턴이라고 간주하지 않는다.

각 플레이에는 다음 원본 기록을 보관한다.

- 원곡 버전·분석 키·구간·카탈로그 해시, 당시 난도 계산 버전과 값, 박자·템포·보기 순서.
- 첫 제출부터 최대 세 번까지의 조각·타이 답과 활성 시간, 서버의 독립적인 재채점 결과와 도움 단계.
- 최초 청취·재청취의 시작과 종료, 완료 여부. 앱을 닫다가 재생이 끊겨도 시작한 청취를 보존한다.
- 화면 비활성 시간을 제외한 활성 풀이 시간, 중단 횟수.
- 동일 구간과 동일 소리 리듬에 대한 **이 기기·계정에서의** 과거 노출 횟수. 다른 기기의 노출까지 안다고 주장하지 않는다.

교정 제출을 여러 독립 표본으로 세지 않는다. 개인의 반복 플레이와 첫 노출을 나눠 검토한다. 청취·시간 기록은 클라이언트 관찰값이며 부정행위를 막는 시험 증거는 아니다. 이번 버전은 자동으로 난도 가중치나 개인 약점을 확정하지 않는다.

세트 완료 또는 시작 화면에서 CSV로 기기 기록을 공유할 수 있다. 서버 기록은 다음으로 내보낸다.

```powershell
docker compose --env-file backend/.env exec -T api python manage.py export_rhythm_calibration --user-id 1 > rhythm-calibration.csv
```

## 저장과 인증

기기 기록과 미전송 기록은 기존 `LocalStore`와 같은 **서버 주소+프로필 ID** 디렉터리에 저장한다. 로그아웃·계정 전환 뒤 다른 사용자에게 옮기지 않는다. 계정 삭제의 기존 기기 정리에도 함께 포함된다. 미완료 문제는 다시 열어 이어서 풀 수 있다.

실서버에서는 완료된 문제를 `POST /api/v1/drills/rhythm/plays/`로 전송한다. Bearer 인증과 기존 인증 세대 검사를 사용한다. `Idempotency-Key`는 고정된 `client_play_id`다. 서버는 카탈로그·출처 해시를 검증하고 직접 채점한 뒤 불변 기록을 저장한다. 같은 플레이를 다른 전송 키로 보내도 중복 생성하지 않는다. 다른 내용으로 덮어쓰면 409다. 실패한 기록은 기기에 보관하고 재시도할 수 있다.

`GET`은 로그인한 사용자의 기록만 30개씩 반환한다. `RhythmPlay.user`는 CASCADE이므로 계정 삭제 시 서버 기록도 제거된다. 문제 분석은 개인 데이터와 분리해 유지된다. 계정 삭제를 우회해 파일을 다시 만드는 처리는 하지 않는다.

데모에서도 채점은 실제 리듬 비교로 수행한다. 데모 기록은 기기에만 저장하며 서버에 저장됐다고 표시하지 않는다.

## 보류 사례와 확장

[v3 보류 구간](RHYTHM-PUZZLE-V3-EXCEPTIONS.md)에 57개를 기록했다. 39개는 구간 바깥 타이, 2개는 7/8 박 묶음 미정, 16개는 Feature v1의 박 단위 분석 미지원(일반 초급 2/2 4구간과 클래식 3/2·6/4·2/2 각 4구간)이다. 이전 v2 설명에서 초급 4구간을 7/8로 쓴 것은 오기이며 실제 박자는 2/2다. [v2](RHYTHM-PUZZLE-V2-EXCEPTIONS.md)·[v1](RHYTHM-PUZZLE-EXCEPTIONS.md) 보류 기록도 보존한다. 정답을 단순하게 바꿔 출제하지 않는다. 내부의 박·마디를 넘는 타이는 출제 가능하다.

현재 실제 출제 풀은 모두 480 PPQ로 정확히 재생된다. 앞으로 이 해상도로 표현되지 않는 잇단음, 중첩 잇단음, 마디를 넘는 잇단음, 정답 조각이 너무 많은 경우가 나오면 이유와 구간을 보류 목록에 추가하고 사용자에게 보고한다. 문제를 추가할 때는 카탈로그를 재생성하고 변경된 풀을 검토한다. 기존 배포 카탈로그의 해시나 의미를 덮어쓰지 않고 버전을 올린다.

## 개발 검증

```powershell
python scripts/build_rhythm_game.py --check
python scripts/build_rhythm_game.py --v2 --check
python scripts/build_rhythm_game.py --v3 --check
python scripts/test_rhythm_game.py
python scripts/test_rhythm_engraving.py
docker compose --env-file backend/.env exec -T api python manage.py test api sori --noinput
```

macOS CI에서 Swift 패키지 테스트와 iPad 호스트 테스트를 실행한다. `RhythmPuzzleIntegrationTests`는 첫 오답 비공개·복구·계정별 저장 격리와 가로/세로 화면 렌더링을 확인하고 스크린샷을 남긴다. Windows 작업 환경에서는 Swift 빌드와 실제 오디오·터치 검증을 실행하지 못하므로 CI와 실제 iPad 확인을 별도로 완료해야 한다.

현재 조각 원본을 다시 조판하려면 MuseScore 4.6.3 설치 후 `python scripts/build_rhythm_engraving.py --catalog-version v3`를 실행한다. Windows는 초기 화면을 띄우지 않는 변환 전용 세션을 사용한다. 문제 파일과 렌더링 파일의 SHA-256을 함께 검증한다. 미완료 v1·v2 세트도 계속 풀 수 있으며, 새 세트만 v3를 사용한다. 버전을 올려도 동일 원곡·버전·마디의 이전 노출 횟수는 이어서 계산한다.

## 2026-11-06 사용성 개선

두 마디는 간격 없이 공유 마디선으로 연결된다. 4/4는 네 칸, 3/4는 세 칸, 6/8은 점4분음표 두 칸을 점선으로 표시한다. 긴 조각 뒤 남은 반 박은 반 폭의 `½박` 빈칸이며 표시와 드롭은 같은 정확한 분수 좌표를 쓴다. Pencil의 작은 흔들림은 탭으로, 드래그는 길게 누르기 없이 처리하고 한 동작이 삭제와 연결을 동시에 하지 않는다. 길이가 맞지 않거나 악보 밖에 놓으면 답은 유지하고 이유를 알린다.

빈칸 상태의 제출은 빠진 마디/박을 강조하며 오답 횟수를 늘리지 않는다. `게임 방법` 메뉴에서 `정답 보고 넘기기`를 고르면 정답을 확인한 뒤 다음으로 이동한다. `skipped`는 정답·3회 오답 공개·중단과 구분해 서버와 기기에 보관한다. 제출 없이 넘긴 기록의 첫 정오는 nil이며 난도 보정 대상이 아니다. 이미 제출한 첫 오답 기록은 이후 넘겨도 그대로 보존한다. 그림이 포함된 튜토리얼은 좌우 스와이프·이전/다음·단계 표시를 제공한다.
