# Memory run v3 UI / v2 catalog

Drill의 Memory run 카드에서 시작한다. Rhythm puzzle과 같은 배경·보라색 강조·둥근 카드·진행 표시를 사용한다. 시험 응시·AI 호출 없이 기기에서 동작한다.

## 사용 흐름

첫 실행에는 네 단계 튜토리얼을 표시하고 이후 `게임 방법`으로 바로 다시 열 수 있다. 그림과 실제 악보·건반이 있는 네 단계 화면은 좌우 스와이프, 이전/다음, 단계 수와 진행 막대를 제공한다. `게임 선택`에서 Memory/Groove를 고른 뒤 별도 화면에서 초급/중급/고급을 고르고 `4문제 시작`을 누른다. 길이 표시는 `2마디` / `2~4마디` / `4마디`다. 출처·라이선스는 설정의 `출처와 이용 조건`에 모았다.

| 단계 | 한 세트의 마디 수 | 4분음표 BPM | 6/8 등의 점4분음표 BPM |
|---|---|---|---|
| 초급 | 2 → 2 → 2 → 2 | 60 | 40; 현재 초급 출제는 단순박자만 사용 |
| 중급 | 2 → 2 → 4 → 4 | 84 | 56 |
| 고급 | 4 → 4 → 4 → 4 | 96 | 64 |

메모리는 예비박 한 마디 → 선율 전체 연속 재생 → 시간제한 없는 복원 순서다. 선율 중간의 클릭·대기 마디는 제거하고 원곡 쉼표는 유지한다. 전체 선율을 한 번에 예약해서 마디 경계 타이가 다시 발음되지 않는다. `바로 듣기`와 `예비박부터 듣기`는 각각 바로 누를 수 있는 버튼이며 두 방식 모두 답을 유지한다. 화면에 표시하는 BPM과 모든 재생은 실제 오디오의 settings.bpm을 사용한다.

그루브는 최초 예비박 → 한 마디 듣기 → 즉시 입력 → 다음 마디 듣기로 진행한다. 준비용 한 마디는 없고 입력 시간은 두 마디이며 일찍 채우면 다음 박에 진행한다. 기존 180ms 조기 입력 경계와 예약 여유를 유지한다. 원본 악보에서 마디를 잇는 타이가 발췌의 내부 또는 양 끝 경계에 있으면 Groove에서 제외한다. 기존 Memory 카탈로그는 그대로 두고 `memory-groove-v1.json`에 카탈로그 해시와 제외 구간 91개를 고정했다. Groove는 5,645개 발췌를 사용하며 Memory는 기존 5,736개를 유지한다.

모든 단계에서 첫 음은 비워 두고 건반·음이름으로 안내하며 직접 눌러 입력한다. 잘못된 시작음은 입력 순서를 밀지 않고 다시 안내한다. 첫 음은 알려준 값이므로 채점에서 제외한다. 리듬·쉼표·붙임줄은 주어지고, 옥타브를 포함한 음높이 순서를 채점한다. 결과를 리듬 받아쓰기 실력이나 기억력 점수로 해석하지 않는다.

마디를 눌러 수정할 곳을 선택하고 한 음 취소·마디 지우기를 제공한다. 첫 음도 지우기·취소로 제거되면 안내가 다시 나타난다. 채워진 마디를 선택한 뒤 건반을 누르면 해당 마디 전체를 비우고 첫 음부터 입력하며, 되돌리기는 이 변경을 한 번에 복원한다. 제출 후 위에 정답 전체, 아래에 입력 악보 전체를 같은 음표 간격으로 동시에 비교하고 원본·답안 재생, 재도전을 제공한다. 네 번째 문제 다음은 세트 결과다. 문제 전환은 1초 대기 후 시작하며 앱 비활성·도움말·닫기가 대기 중 재생도 취소한다.

## 비전공자용 초급

초급은 단순히 전체 자료의 낮은 점수 구간을 뽑지 않는다. 첫 플레이를 위한 별도 조건을 적용한다.

- 2/4·3/4·4/4의 온전한 두 마디, 3~8번의 발음 시작.
- 원래 조성이 다장조이며 임시 변화음 없이 C4~C5의 흰건반만 사용.
- 전체 음역 7반음 이하, 최대 도약 5반음 이하, 평균 음정 3반음 이하.
- 가장 짧은 실제 음 길이는 8분음표 이상, 엇박 발음 비율은 0.34 이하.
- 첫 두 문제는 추가로 3~5음, 음역 5반음 이하, 모든 음정이 2반음 이하인 반복·순차 선율.

현재 초급 후보는 69개 원곡의 132구간이다. 이 중 첫 두 문제 후보는 42개 원곡의 64구간이다. 첫 음을 제외하면 입력해야 하는 답은 첫 두 문제에서 2~4음이다. 초급은 C4~C5 한 옥타브 건반과 도레미 이름을 표시한다. 쉬운 조건을 만족하면 클래식 구간도 포함하지만 곡 수 비율을 맞추기 위해 어려운 구간을 끼워 넣지 않는다.

실제 비전공자 사용성 검증은 별도다. 초기 플레이 결과에 따라 조건과 속도를 조정한다.

## 문제 데이터와 원본 보존

`Resources/memory-run-v2.json`에는 기존 923개 선율, 중급 청음 11개, 클래식 33개, 총 967개 소스의 5,736개 발췌 구간을 넣었다. 2마디 구간 3,809개, 4마디 구간 1,927개다. 고난도 청음과 별도 초급 청음 묶음은 이번 추가 대상이 아니다. 기존 197개 다장조·가단조 제한은 해제했다.

각 8마디 소스에서 1–2/3–4/5–6/7–8, 1–4/5–8을 추출한다. 구간 밖 타이가 있는 34구간과 발음 시작이 두 개 미만인 38구간은 보류했다. 자세한 목록은 `memory-import-report.json`에 있다. 원본 음정·음가·조성·쉼표·타이·잇단음·빔은 보존한다. 새 XML의 원래 템포 지시는 제거하고 게임 정책의 템포로 재생한다. 원본 시험 악보와 템포 정책은 변경하지 않는다.

원본 최신 QuestionVersion, 원본 XML SHA-256, 게임용 XML SHA-256, Feature v1 analysis key를 함께 남긴다. 문제 출처와 음악 메타데이터는 유지하고 게임 화면의 출처 설명은 제거했다. 기존 라이브러리 MusicXML과 CC BY-SA 4.0 이용조건은 설정에서 확인한다. 피아노는 기존 YDP Grand Piano와 velocity 76을 사용한다.

## 실험 난이도: memory-burden-v1

Feature v1의 사실 추출 결과를 사용하지만 실험 점수는 별도 버전이다. 정확히 출제되는 2·4마디 내부의 연결 음정만 사용하며, 구간 밖 음정은 가져오지 않는다. 한 발음이 타이로 여러 음표에 나뉘어도 한 번으로 센다.

| 성분 | 초기 계산 |
|---|---|
| 음정 P | `0.35×min(평균 절대 반음/7,1) + 0.25×7반음 이상 도약 비율 + 0.20×min(조성 밖 음 비율,1) + 0.10×min(음역/24,1) + 0.10×트라이톤 계열 비율` |
| 기억 부담 M | `0.55×min(발음 수/(마디 수×8),1) + 0.45×(1−연속 세 음정 패턴의 반복률)` |
| 리듬 R | `0.45×박 바깥 발음 비율 + 0.35×min(박당 발음 수/4,1) + 0.20×잇단음 발음 비율` |
| 원점수 | `0.55P + 0.30M + 0.15R` |

연속 세 음정 패턴은 방향이 있는 반음 간격 세 개다. 반복률은 `1−고유 패턴 수/전체 패턴 수`이고 패턴이 만들어지지 않는 짧은 선율에서는 0으로 둔다. 음표 표면의 임시표 개수·빔 모양은 이 점수의 원인이 아니다.

2마디끼리, 4마디끼리 원점수의 중간 순위를 0~100으로 변환한다. 분모 2 박자는 이 게임 실험에서 2분음표 단위, 겹박자는 점4분음표 단위, 나머지는 4분음표 단위를 사용한다. 이것은 Feature v1의 미확정 박 묶음을 덮어쓰지 않는다. 이 점수는 절대 난이도·사용자 능력·학습 효과에 대한 검증값이 아니다.

난이도별 선택 가중치는 `0.20 + exp(−0.5×((점수−중심)/30)²)`이며 중심은 35/50/65다. 모든 점수에 양의 가중치를 줘 단계 사이에서 선율이 겹친다. 초급은 위의 입문 조건을 추가로 적용한다. 두 중·고급 단계를 완전히 분류하지 않는다.

선택 가능한 소스 종류를 기존 라이브러리 60%, 중급 청음 20%, 클래식 20% 가중치로 먼저 고르고 해당 자료가 없으면 가능한 종류끼리 정규화한다. 같은 소스에 발췌가 많다는 이유로 더 자주 뽑히지 않게 소스별 후보 수로 가중치를 나눈다. 한 세트에서는 같은 소스와 동일 소리 패턴을 반복하지 않는다.

## 기록과 후속 연결

로그인된 사용자는 기존 `LocalStore`의 서버 origin·사용자별 폴더에 `memory-observations-v2.json`을 저장한다. 게스트는 별도 폴더다. 기존 계정 삭제의 로컬 폴더 삭제도 이 기록에 적용된다.

기록에는 세트/문제 ID, 원본·분석·난도 버전, 출제 구간, 실제 BPM, 음높이 정답·입력·제공된 첫 음, 최초/재노출 횟수, 재생 시작·완료 횟수, 입력 활동 시간, 중단, 제출·포기·기술 오류를 남긴다. 초급의 첫 음은 정답률 계산에서 제외한다. 재생을 듣기 시작하지 않은 포기는 청취 노출로 세지 않는다. 앱 종료로 남은 진행 중 기록은 다음 실행에서 중단 기록으로 바꾸며 오답으로 바꾸지 않는다.

기기 기록과 개발 검증용 CSV 생성은 유지하며 게임 화면의 공유·저장 안내는 제거했다. 서버 업로드·개인화 프로필·난이도 자동 재학습은 아직 연결하지 않았다. 기록은 약점과 난도 조정의 단서로 사용한다.

## 악보와 검증

기존 시험용 NativeScoreRenderer에 Memory run 전용 간격 옵션을 추가했다. 마디 폭은 음표 수·음가·조표를 기준으로 계산하고 화면 가로폭으로 늘리지 않는다. 기본 두 마디를 나란히, 네 마디는 두 줄로 보여주며 작은 화면은 한 열로 바꾼다. 밀집된 마디는 축소 후 가로 스크롤을 제공한다. 기존 시험 악보 좌표와 제출용 오선지 좌표는 유지한다.

```powershell
python scripts/build_memory_game.py --check
python scripts/test_memory_game.py
python scripts/test_melody_library.py
```

macOS CI는 Swift의 전체 967개 소스·모든 발췌 재생/답안 일치, 세트 계획·첫 음 보호·입문 선율·악보 간격을 검사한다. iPad 호스트 검사는 두 모드의 오디오, 4문제 진행·기록, 지연 재생 취소와 악보 캡처를 포함한다. 실제 화면·음색·터치와 비전공자의 체감 난이도는 새 IPA를 설치해서 확인해야 한다.

## 오프라인 악보 조판

`memory-glyphs-v1.json`은 MuseScore 4.6.3/Leland에서 추출한 29개 음표·쉼표·음자리표·임시표·기 꼬리 윤곽이다. `scripts/build_memory_glyphs.py`로 재생성한다. 정답과 동적 답안을 같은 Canvas 조판기로 그린다. 빔·점·붙임줄·잇단음과 마디 사이 연결은 원본 MusicXML 구조를 유지한다. 4마디는 두 마디씩 두 줄로, 비교 악보는 같은 원본 리듬 좌표와 정답/답안 합산 음역을 사용한다. 원본 문제 풀과 해시는 변경하지 않았다.

기존 기기 기록은 보존한다. 새 기록은 `input_policy=guided-first-manual-v3`, 예비박/직접 재청취 횟수, 재도전의 원본 기록 ID를 별도로 저장한다. 과거 미리 입력된 첫 음 기록과 새 수동 안내 기록은 같은 조건으로 합산하지 않는다.

## 2차 사용성 피드백

문제 풀이·문제별 결과에서 ×는 난이도 선택으로 한 단계 돌아가며 재생과 예약된 시작을 중단한다. 난이도 선택의 ×는 Memory/Groove 선택, 그 화면의 ×는 Drills로 이동한다. 세트 완료 화면의 ×는 Memory/Groove 선택으로 이동한다. 결과 화면에는 게임 방법 버튼이 없다. 마지막 문제는 `결과 보기`, 세트 완료 후에는 `다시 n문제 풀기`와 `난이도 변경하기`를 제공하며 n은 실제 세트 길이다.

새 세트는 이 계정·기기에서 실제 들은 최근 20문제의 원곡과 최근 40문제의 동일 소리 패턴을 우선 피한다. 풀이를 시작하지 않은 문제는 청취 기록으로 간주하지 않는다. 후보가 부족하면 먼저 새로운 원곡, 이후 가장 오래전에 들은 원곡 순으로 완화하여 초급 풀이를 막지 않는다. 같은 세트의 원곡·패턴 중복 방지와 기존 난이도·자료 종류 가중치는 유지한다.
