# 멜로디 런 프로토타입

홈의 **멜로디 런 · 미니게임** 또는 사이드바 **미니게임 → 멜로디 런**으로 시작합니다. 서버와 AI 채점 없이 오프라인에서 동작합니다. 기존 시험의 API·답안·저장·재생 계획에는 변경이 없습니다.

## 화면 디자인

기존 SORI의 보라색 `#6450D9`, 옅은 보라색 카드, 밝은 배경, 둥근 모서리를 사용합니다. 멜로디 런 입구에는 보라색 그라데이션과 큰 피아노 아이콘을 사용합니다.

- **설정:** 메모리/그루브 두 카드를 나란히 배치하고, 문제·플레이 구간과 템포·진행 정책을 두 열로 정리합니다. 문제 검색, 랜덤 선택, XML 추가를 제공합니다.
- **플레이:** 전체 화면으로 전환합니다. 위에서부터 모드·문제·BPM·일시정지, 듣기/비트/입력 표시와 박동 점, 현재 마디 악보, 마디 이동 표시, 건반, 취소·제출 버튼 순서입니다. 사이드바와 긴 전환 애니메이션은 없습니다.
- **피아노:** 화면 높이의 약 34%(190–290pt)를 하단에 고정합니다. 최소 두 옥타브를 제공하고 문제 음역에 맞게 확장합니다. 1194pt 가로 iPad에서 일반적인 두 옥타브는 흰건반 약 76pt, 검은건반 약 47pt입니다. 검은건반은 높이 62%이고 상단에서는 흰건반보다 먼저 판정합니다. 건반명과 눌림 색상, VoiceOver 활성화를 제공합니다.
- **악보:** 기존 NativeScoreRenderer를 한 마디 보기로 재사용합니다. 정답 리듬·쉼표·붙임줄은 자동이고, 미입력 음은 보표 중앙의 흐린 음표로 표시하여 정답 음높이를 노출하지 않습니다. 입력은 즉시 원래 리듬 자리에 나타납니다. 조표와 높은/낮은음자리표를 지원합니다.
- **결과:** 정확도·점수·최고 콤보를 먼저 보여주고, 마디별 원본/입력 악보와 각 음의 `정답 → 입력`을 비교합니다. 틀린 음은 빨간색이며, 미입력도 명시합니다. 전체·마디별 원본/입력 재생, 정지, 재도전, 다음 문제가 있습니다.

## 플레이 규칙

**메모리:** 한 마디 예비박 → 각 마디 듣기와 설정한 0–8비트 간격 → 전체 복원. 시간제한이 없습니다. 마디를 채우면 다음 마디로 넘어가며, 한 음 취소로 이전 마디까지 되돌릴 수 있습니다. 마디 표시를 눌러 수정할 수도 있습니다. 완성 후 수동 제출합니다.

**그루브:** 한 마디 예비박 → 한 마디 듣기 → 한 마디 비트 → 설정한 1–4마디 길이의 입력을 반복합니다. 미입력은 빈칸으로 남깁니다. 일찍 완료했을 때 기다리거나 **다음 박**에 진행할 수 있습니다. 다음 박 진행은 최소 160ms 예약 여유를 두며 오디오 시계를 재시작하거나 탐색하지 않습니다. 다음 구간이 예약된 후 수정하더라도 이미 정해진 다음 박은 유지됩니다. 현재 입력 마디의 한 음 취소와 전체 지우기를 제공합니다.

두 모드에서 2·4·8마디와 시작 마디를 선택합니다. BPM은 **4분음표 기준 40–180**, 6/8·9/8·12/8의 비트는 점4분음표입니다. 정확도는 옥타브를 포함한 MIDI 음높이의 일치 비율입니다. 붙임줄로 이어진 음은 한 번만 입력/채점합니다. 점수는 정답당 100점에 연속 정답 보너스(음당 최대 100점)를 추가합니다. 결과 이전에는 정답 여부를 알려주지 않습니다.

입력 단계 밖에서도 건반 소리는 들리지만 답안에는 기록하지 않습니다. 화면을 벗어나거나 인터럽트·헤드폰 분리가 발생하면 소리를 정지합니다. 복귀 시 명시적으로 계속하기를 눌러야 하며, 메모리는 듣기 시작부터, 그루브는 현재 마디의 듣기부터 재개합니다. 무제한 복원 중에는 입력 단계 자체로 돌아옵니다. 입력은 유지하지만 앱 종료 후 라운드를 복구하는 영속 저장은 이번 범위에 포함하지 않습니다.

## 구조와 재사용

- `Core/MelodyRun.swift`: 시험과 독립된 라운드, 음 입력·취소·채점, 비트 기반 구간 계획 및 조기 진행.
- `Core/MelodyXMLParser.swift`: 기존 SafeXML/XMLNode·MusicScore·MusicEvent·ScoreSymbol 사용. 시험용 MusicXMLParser는 그대로 유지합니다.
- `Core/PianoGeometry.swift`: 검은/흰건반의 공통 표시·터치 좌표.
- `Services/MelodyRunAudio.swift`: 기존 PianoAudioGraph, 고정 GeneralUser GS 피아노, 예비박 WAV, MIDIFile 사용. 게임용 그래프 안에서 참조 피아노/입력 피아노/비트를 분리합니다. 하나의 AVAudioSequencer 시계에서 비트가 흐르고, 다음 참조 음을 앞서 예약합니다. 키는 시퀀서와 별도 sampler로 즉시 발음합니다.
- `Services/MelodyRunModel.swift`: 게임 상태, 로컬 문제, 입력 시간 경계, 오디오 생명주기.
- `Views/MelodyRunView.swift`, `Views/MelodyPianoView.swift`: 미니게임 허브와 독립 화면. UIKit 멀티터치 키보드는 손가락 이동, 중복 음의 누름 수, 취소/화면 해제도 처리합니다.

새 게임은 허브에 추가하고 별도 모델/규칙을 두면 됩니다. 시험 모델의 상태나 서버 채점 엔드포인트를 공유할 필요가 없습니다.

## 문제 추가와 출처

현재 제공된 1047문제에서 **923개**를 포함했습니다. 제외 124개(못갖춘마디 86, 480 PPQ로 정확히 표현하지 못하는 음가 19, 반복/다성부 7, 미지원 음표 7, 화음/꾸밈음 2, 음자리표 1, 표시 음가 불일치 2)는 `melody-import-report.json`에 기록되어 있습니다. 조성·박자·음높이·리듬은 바꾸지 않았습니다. 레이아웃·가사·사용하지 않는 악기 정보와 외부 DTD 선언만 제거했습니다. 출처·라이선스는 앱에 표시하고 원문을 번들에 포함합니다.

저장소 빌드에 추가할 때:

```powershell
python scripts/import_melody_library.py --source ../MusicXML --append
```

원본 1047문제 컬렉션으로 다시 생성할 때:

```powershell
python scripts/import_melody_library.py --source ../ear_training_8bars_1047_XML_only/ear_training_8bars_1047
```

`--source` 없이 실행하고 작업 폴더의 MusicXML이 비어 있어도 기본 컬렉션으로 생성됩니다. `problem_list.csv`가 있는 컬렉션 루트를 지정하면 개별 출처와 조성 이름을 유지합니다. 앱 안의 **XML 추가**는 파일을 검증하고 Documents/MusicXML에 복사하므로 다시 빌드하지 않아도 됩니다. `.xml`/`.musicxml`만 지원하며 압축 `.mxl`은 가져오기 대상이 아닙니다.

## 검증 및 남은 확인

Windows에서 `python scripts/test_melody_library.py` 및 기존 시험 회귀 검사 5개 스크립트를 실행합니다. 원본과 번들의 조성·박자·모든 음높이·음가·붙임줄·빔을 비교합니다. Swift 핵심 테스트는 전체 923개 읽기, 2·4·8마디 분할, 원음 입력 100% 채점, 미입력·옥타브 오류·콤보·취소·박 경계·검은건반 좌표를 검사합니다. iPad 호스트 테스트는 두 모드와 두 조기 진행 정책, 일시정지 복귀, 결과 재생, 시험 복귀, 악보·키보드 캡처를 추가했습니다.

```sh
python3 scripts/fetch_soundfont.py
swift test --package-path frontend
xcodebuild -project frontend/IPadApp/IPadApp.xcodeproj -scheme IPadApp \
  -destination 'platform=iOS Simulator,name=<설치된 iPad>' \
  -derivedDataPath build/DerivedData CODE_SIGNING_ALLOWED=NO \
  -only-testing:IPadAppTests/MelodyRunIntegrationTests test
```

2026-10-29 Windows에서 기존 시험 회귀 19개와 새 문제 라이브러리 검사 5개, 총 **24개가 통과**했습니다. 원본 923개 보존과 XML 추가 시 기존 목록 유지도 확인했습니다.

현재 Windows에는 Swift/Xcode가 없고 Docker 엔진도 실행되지 않아 Swift 컴파일과 iPad 테스트는 실행하지 못했습니다. 물리 iPad에서 건반 입력 지연·스피커/블루투스 경로·멀티터치·빠른 반복·작은 iPad의 건반 폭을 확인해야 합니다. 특히 AVMusicTrack 실행 중 예약의 실기기 동작과 화면 부하가 큰 상황에서 160ms 예약 여유가 충분한지 검증해야 합니다. OS가 오디오 지연을 결정하므로 블루투스의 지연 자체를 앱에서 제거하지는 않습니다. Swift/Xcode CI에 새 테스트를 포함했습니다.
